### Pod self-removal: what the docs say (2026-10-06, docs only, no spend)
- RunPod's pod environment-variable reference lists `RUNPOD_POD_ID` and a `RUNPOD_API_KEY` described as limited in scope to the pod itself (docs.runpod.io/pods/references/environment-variables).
- The runpodctl overview says every pod comes with `runpodctl` preinstalled and a Pod-scoped API key (docs.runpod.io/runpodctl/overview).
- The current runpodctl reference spells removal `runpodctl pod delete <pod-id>`; older releases use `runpodctl remove pod <pod-id>`, so the watchdog tries both, then GraphQL `podTerminate`.
- Unverified until the first real pod: whether the Pod-scoped key may terminate (not only stop) its own pod, which runpodctl version the image carries, and whether the GraphQL endpoint accepts that key; a `TERMINATE_FAIL` line then leaves the laptop backup timer as the only stop.
- Unverified by design: on a pod without a network volume, files flushed at the cut die with the pod unless the laptop downloaded them first; the watchdog removes the pod right after the flush.
